# Gram Market — hpl_ruralMarket_prototype

A rural-market price finder for Indian agricultural commodities. It helps a farmer
answer two questions:

1. **Which market pays the most for my crop?** — accounting for transport cost from
   where I am, not just the raw price.
2. **Where should I take my whole harvest (a basket of several crops)?** — the ONE
   market that nets the most when selling everything together.

The UI is bilingual (English / Hindi) and centred on a full-screen Leaflet map.

## What it does

- **Price discovery** — current modal prices (₹/kg) for ~96 commodities across ~196
  markets in 9 states, searchable by name/district/state, filterable by commodity and state.
- **Price trends** — per commodity, per market: min / max / modal price and a last-30-days
  history view.
- **Geospatial arbitrage / comparison** — pick up to 2 markets, see per-market distance
  from your location, transport cost, and **net revenue** (price − transport), plus a
  driving-route line on the map (OSRM routing).
- **Best spot** — one click shows the single most profitable market for the chosen crop,
  flies the map to it and draws the route.
- **Advance Search (basket analysis)** — enter several crops + quantities (e.g. 200 kg
  tomato + 50 kg potato); the backend ranks every market by combined net revenue and
  highlights the best market with a per-crop revenue breakdown, transport, net, and how
  other markets compare. Markets missing data for any crop are excluded from "best" but
  listed with a note. The result opens the best location on the map with directions.

## The core math

- Prices are reported by Agmarknet in ₹/quintal and are converted to **₹/kg**.
- Transport cost = `0.1 ₹/kg·km × road distance (km) × total kg` (see `backend/src/config.ts`).
- For a single commodity: `net revenue = modal price − transport cost (per kg)`.
- For a basket: `net revenue = Σ (modal price × qty) − transport cost` (transport once,
  on total basket weight).
- Distances use the haversine formula for ranking and OSRM driving routes for the
  on-map polyline.

## Architecture

```
frontend/   React 19 + TypeScript + Vite + Tailwind v4 + Leaflet (react-leaflet)
backend/    Express + TypeScript (tsx) REST API on :4000
frontend →  Vite dev server proxies /api → http://localhost:4000
```

### Frontend

- `src/pages/MapPage.tsx` — full-page map with search, filters, markers, compare/cost
  cards, route polylines, "Best spot" button, and the Advance Search entry point (bottom
  FAB).
- `src/pages/DashboardPage.tsx` — trends / history dashboard.
- `src/components/map/` — reusable map widgets (`FlyTo`, `ComparePanel`, `MandiCostCard`,
  `PriceTrend`, `Row`, icons, shared types).
- `src/components/advance/` — the Advance Search UI (`AdvanceSearchButton`,
  `AdvanceSearchModal`, `BasketResultPanel`).
- `src/api/client.ts`, `src/api/routing.ts` — typed API + OSRM route helpers.

### Backend (`backend/src/`)

- `store.ts` — in-memory dataset (markets, commodities, prices, history).
- `routes.ts` — all `/api/*` endpoints + validation + reason strings.
- `basket.ts` — pure basket-analysis computation.
- `geo.ts` — haversine distance. `config.ts` — constants (port, transport rate, defaults).

### API

| Endpoint | Purpose |
|---|---|
| `GET /api/states` | state list |
| `GET /api/markets?state=` | markets (optionally filtered) |
| `GET /api/commodities` | commodity list (with Hindi names) |
| `GET /api/prices` | price rows for a commodity (markets, format) + optional state/origin |
| `GET /api/prices/latest` | latest modal price per market, trend, change |
| `GET /api/prices/history` | last-N-days history per market |
| `GET /api/compare` | compare two markets for a commodity from an origin |
| `GET /api/recommend` | best single market for a commodity from an origin |
| `POST /api/analyze` | basket analysis (best market for a set of crops + quantities) |

## Dataset

- Source: Agmarknet marketwise report, dated **2026-09-06**.
- Raw CSV lives in `backend/csv/`; `scripts/format-csv.ts` + `scripts/generate-data.ts`
  build the JSON dataset in `backend/data/`.
- Daily trends are synthetic estimates anchored on real modal prices (generated by the
  backend), since only a snapshot is available.
